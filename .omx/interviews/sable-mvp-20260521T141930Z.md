# Deep Interview Summary: sable MVP

## Metadata

- Profile: standard
- Context type: greenfield
- Final ambiguity: 0.16
- Threshold: 0.20
- Context snapshot: `.omx/context/sable-mvp-20260521T141930Z.md`

## Confirmed Decisions

- Build a minimalist select-shop website named `sable`.
- Use Next.js App Router, TypeScript, CSS Modules, and global CSS.
- Do not use a UI library.
- Preserve the supplied Figma desktop tone as the primary visual reference.
- Extend tablet and mobile layouts reasonably because only desktop Figma screens exist.
- Implement `Men`, even if the Figma layer text says `Man`.
- Use gray product image placeholders for MVP.
- Do not implement real authentication or payment.
- Login, Cart, and Checkout are mock flows.
- Cart should use localStorage and support add, remove, and quantity changes.
- Brands click navigates to `/brands`.
- Desktop Brands hover opens a mega menu; each brand navigates to `/brands/[slug]`.
- Mobile navigation uses a drawer; Brands opens as an accordion/tap section.
- Styling is a lookbook area, not a product grid: `/styling` and `/styling/[slug]`.
- Styling data should allow future `relatedProductIds`.

## Pressure-Pass Resolution

The key assumption was whether product-hover UI could translate cleanly to mobile. The resolved plan is:

- Desktop/tablet pointer devices: hover/focus reveals metadata and expands the card in document flow.
- Mobile: first tap reveals product metadata; tapping the revealed title or a dedicated detail area navigates to the detail page.
- Fallback if mobile tap interaction feels heavy during QA: show metadata by default on mobile.

## Non-Goals

- No production auth.
- No production checkout.
- No backend, CMS, Supabase, or API layer in MVP.
- No real product imagery in MVP.
- No UI library.
- No exact tablet/mobile Figma recreation, because those designs do not exist.

## Decision Boundaries

Codex may decide:

- Exact responsive grid counts, spacing, and drawer layout as long as the Figma tone is preserved.
- Seed data shape and mock content names.
- Cart localStorage key and reducer structure.
- Search-result empty state copy.
- Whether mobile product metadata defaults visible if tap-to-expand proves awkward.

Codex should ask before:

- Adding dependencies beyond Next/React/TypeScript tooling.
- Introducing a backend or external service.
- Changing the Figma-driven desktop visual direction.
- Adding real auth/payment.

## Acceptance Criteria

- Header contains all requested menu items and logo links home.
- Menu hover/focus visually bolds items.
- Desktop Brands hover opens a mega menu; mobile Brands opens inside drawer.
- `/brands`, `/brands/[slug]`, `/new-in`, `/women`, `/men`, `/life`, `/sale` render product-list style pages where relevant.
- `/styling` renders lookbook cards and `/styling/[slug]` renders a mock detail.
- Product card metadata is hidden by default on pointer-hover layouts and expands in flow on hover/focus.
- Product detail pages show placeholder image, brand, product name, price, description, sizes, and add-to-cart.
- Search overlay opens from Search, submits Enter to `/search?q=...`, and searches product name, brand name, and category.
- Cart persists in localStorage and supports add, delete, and quantity changes.
- Checkout is a non-payment mock page.
- Desktop, tablet, and mobile layouts are usable and visually aligned with the Figma tone.
